Unit 1: Fundamentals of Algorithms

Requirements of Algorithms & Why Analyze

Definition

An algorithm is a formal, step-by-step procedure used for calculations, data processing, and automated reasoning. It is not merely a piece of code or a vague idea; strict "Algorithm Requirements" dictate that it must be: 1. Finite (it must eventually stop), 2. Definite (each step must be clear and unambiguous), 3. Effective (operations must be basic enough to be done by a human with paper), 4. Inputs (zero or more distinct inputs), and 5. Outputs (at least one output related to input).

Analyzing algorithms means determining the amount of resources (such as time and storage) necessary to execute them. This theoretical study is separate from the actual running of the program on a specific machine. It focuses on the growth rate of resources as input size increases, rather than seconds or milliseconds.

Time & Space Complexity

Analyzing Requirements doesn't involve complexity itself, but enforcing "Finiteness" ensures that Time Complexity is not infinite. Without finiteness, analysis would be impossible because the function T(n) would be undefined or divergent. Efficiency analysis seeks to minimize T(n) (Time) and S(n) (Space).

What's it is for

These definitions serve as the constitutional law of computer science. Requirements filter out "bad" procedures (like infinite loops or vague instructions). Analysis serves as a prediction tool, allowing engineers to estimate the performance of a system before building it, saving millions of dollars in wasted development time on inefficient solutions.

How it solve our problem

By strictly defining what an algorithm is, we avoid logical pitfalls where a program might hang or produce random results. By analyzing them, we can mathematically prove that Solution A is superior to Solution B for large inputs, independent of the hardware used (supercomputer vs. smartphone).

Real world example

A Cooking Recipe: A valid recipe is an algorithm. It has Inputs (Ingredients), Outputs (Dish), Definiteness ("Add 1 tsp salt", not "Add some salt"). If a recipe said "Stir fast" (ambiguous) or "Cook until world ends" (infinite), it would fail the requirements. Bridge Design: Engineers calculate load capacity (Analysis) before building the bridge, rather than building it and driving a truck over it to see if it collapses.

Why we choose only this rather than else

We choose rigorous analysis over "trial and error" or "benchmarking" because benchmarks are unreliable. A fast computer might run a bad algorithm quickly for small inputs, masking its inefficiency. Only mathematical analysis reveals the true scalability (Asymptotic behavior) that matters for big data.

Problems & Instances

Definition

In algorithmic theory, a Problem is the abstract question to be solved, defined by a general description of its parameters and a statement of what solution is required. An Instance is a specific, concrete case of that problem with fixed input values.

"Sorting" is a Problem. "Sort the list {5, 1, 9, 3}" is an Instance. The distinction matters because algorithms are designed to solve the *Problem* (all cases), while execution happens on an *Instance*.

Time & Space Complexity

Time complexity T(n) is expressed as a function of the size of the instance (typically denoted as 'n'). We do not calculate complexity for a single instance (which takes constant time), but for the set of all possible instances of size n.

What's it is for

This concept allows us to generalize. We don't want an algorithm that only sorts numbers starting with '5'; we want one that sorts any list of numbers. Separation of Problem and Instance is the foundation of reusable software libraries.

How it solve our problem

It creates a standard interface. The problem definition acts as a contract (e.g., "Input: Array A, Output: Sorted A"). The algorithm implements this contract. We can test the algorithm against thousands of different instances to verify correctness.

Real world example

GPS Navigation: The Problems is "Find shortest path from A to B". An Instance is "My house to the Airport today". Google Maps writes one code base to solve the general Problem, which then handles billions of unique Instances daily.

Why we choose only this rather than else

If we focused only on instances, we would hard-code solutions (e.g., a lookup table). This is impossible for infinite domains. Generalizing to Problems allows us to write logic (loops, conditions) that handles unseen data.

Asymptotic Notation (O, Ω, Θ, o, ω)

Definition

Asymptotic notations are mathematical tools used to describe the limiting behavior of a function. They define "boundaries" for the growth of an algorithm's running time as input size approaches infinity.
Big-O (O): Upper Bound. The algorithm will never be slower than this.
Omega (Ω): Lower Bound. The algorithm will never be faster than this.
Theta (Θ): Tight Bound. The algorithm runs exactly within this corridor.

Little-o and Little-omega are stricter versions of O and Ω where the bounds are not tight (inequality is strict).

Time & Space Complexity

These are the language of complexity. Instead of saying "The code takes 3n² + 5n + 2 microseconds", we simply say "It is Θ(n²)". This abstraction removes hardware-specific constants and low-order terms that become irrelevant for large n.

What's it is for

They allow for quick, high-level comparison of algorithms. They categorize algorithms into "efficiency classes" (Linear, Logarithmic, Quadratic, Exponential). This is crucial for selection; an O(n) algorithm is objectively better than an O(n²) one for large data sets, regardless of implementation details.

How it solve our problem

By focusing on the dominant term (e.g., n²), we simplify the math. We define a "Worst Case" (Big-O) to guarantee performance safety guarantees—critical for real-time systems where missing a deadline isn't an option.

Real world example

Buying a House: You ask the price. The agent says "It's in the high 6-figures". This is an Order of Magnitude estimate (Theta). You don't care if it's $800,001 or $800,005; the "magnitude" tells you if you can afford it. That is Asymptotic analysis.

Why we choose only this rather than else

Exact instruction counting is tedious and brittle (changes if you change CPU). Asymptotic notation is robust and remains true whether you run the code on a 1990 PC or a 2025 Supercomputer.

Iterative vs Recursive Algorithms

Definition

Iterative Algorithms use looping constructs (for, while, do-while) to repeat a block of code until a condition is met. The state is maintained explicitly in variables updated in each loop.
Recursive Algorithms solve a problem by defining a function that calls itself with a smaller subset of the original input. The state is maintained implicitly by the system's Call Stack.

Analyzing control structures implies looking at how these loops or recursive calls contribute to the total step count (e.g., a loop running 'n' times inside a loop running 'n' times = n²).

Time & Space Complexity

Recursive: Usually Space O(n) due to stack depth. Time overhead for function calls.
Iterative: Usually Space O(1) (constant extra space). Faster execution generally due to lack of stack operations.

What's it is for

These are two different programming paradigms. Recursion is often "declarative" (describing what to do), making it perfect for hierarchical data (Trees, Graphs). Iteration is "imperative" (describing how to do it), making it efficient for linear data (Arrays).

How it solve our problem

Recursion solves problems by "Divide and Conquer"—breaking a hard problem into identical small ones. Iteration solves problems by accumulation or incremental progress. Some problems (like DFS traversal) are 10 lines of code in Recursion but 50 lines in Iteration.

Real world example

Looking up a word in a real Dictionary:
Recursive: "Is it in the first half? No. Look in the second half." (Repeat logic on new half).
Iterative: Flip page 1, check. Flip page 2, check. Flip page 3, check. (Or jumping index by index).

Why we choose only this rather than else

We choose Recursion for readability and complex structures (Trees). We choose Iteration for raw performance, memory constraints (embedded systems), and simple linear tasks to avoid Stack Overflow errors.

Amortized Analysis

Definition

Amortized Analysis is a technique used to establish a worst-case bound for the average performance of each operation in a sequence of operations. It differs from Average-Case analysis because it does not rely on probability; it guarantees the average performance over a worst-case sequence.

It considers the fact that in some data structures, expensive operations (like resizing an array) happen very strictly rarely, and their cost can be "spread out" (amortized) over the many cheap operations that caused them.

Time & Space Complexity

Typically proves that an operation is Amortized O(1) (Constant time), even if its true Worst Case is O(n). Real-time complexity is effectively constant implies smooth performance.

What's it is for

It is used for dynamic path-compression data structures (Union-Find) and dynamic arrays (ArrayList/Vector). It gives a more honest picture of performance than strict Worst-Case analysis, which would be overly pessimistic for these structures.

How it solve our problem

We use the Aggregate Method (Sum total costs / N), Accounting Method (Charge $2 for a $1 op, save the $1 for later expensive ops), or Potential Method (Physics energy analogy). These methods mathematically prove the spread cost.

Real world example

Paying Rent: You pay $3000 on the 1st of the month (Expensive operation). For the next 29 days, you pay $0 (Cheap operation). If you "Amortize" the cost, you are "effectively" paying $100/day. The daily experienced cost is low, despite the occasional spike.

Why we choose only this rather than else

If we used strict Worst-Case, we would reject `ArrayList` because "Insert is O(n)" (due to resizing). But `ArrayList` is excellent in practice. Amortized Analysis explains why it is excellent, validating its use in standard libraries.

Unit 2: Solving Recurrences

Generating Recurrence Relations

Definition

A recurrence relation is a mathematical equation that defines a sequence recursively; it expresses the nth term as a function of previous terms. In algorithms, generating a recurrence means translating the logic of a recursive function into a mathematical formula T(n).

For example, if an algorithm splits input in half and does linear work, we write `T(n) = T(n/2) + n`. This step is the bridge between Code and Math.

Time & Space Complexity

The relation itself describes the Time Complexity structure. Solving it (finding the closed form) gives us the Big-O notation.

What's it is for

It models the cost of Divide and Conquer algorithms. Since D&C algorithms invoke themselves, their cost is naturally self-referential. We cannot use simple instruction counting.

How it solve our problem

To analyze a recursive function, we look at three parts: 1. The number of subproblems (a), 2. The size of subproblems (n/b), 3. The cost to divide and combine (f(n)). We combine these into `T(n) = aT(n/b) + f(n)`.

Real world example

Cell Mitosis: One cell divides into two every hour. Population P(t) = 2 * P(t-1). This is a recurrence. Solving it gives P(t) = 2^t (Exponential growth).

Why we choose only this rather than else

There is no other way to analyze recursion. Loop counting fails because the loop limits themselves change in every recursive call.

Range Transformation & Change of Variable

Definition

Change of Variable: A technique to simplify complex recurrences (like `T(n) = 2T(√n) + log n`) by substituting the variable (e.g., let `m = log n`) to transform it into a standard form we know how to solve.

Range Transformation: Adjusting the domain or range of the recurrence to fit standard theorems (like Master Theorem). It involves algebraic manipulation to map a hard problem to an easy, solved problem.

Time & Space Complexity

Does not change complexity, but reveals it. For example, `T(n) = 2T(√n) + log n` solves to O(log n * log log n) via transformation.

What's it is for

Handling "non-standard" recurrences that don't fit the `T(n/b)` mold directly. often seen in advanced algorithm design or number theoretic algorithms.

How it solve our problem

1. Rename `n` to `2^m`.
2. Rewrite equation in terms of `m`.
3. Solve for `m`.
4. Substitute `n` back.
It turns a scary square-root recurrence into a simple linear divide-and-conquer one.

Real world example

Logarithmic Scales: In audio engineering, we convert signal power (Linear) to Decibels (Logarithmic) to make calculations additive instead of multiplicative. This is a change of variable to simplify math.

Why we choose only this rather than else

Without this technique, we would be stuck. Standard Master Theorem fails on `√n`. Variable transformation unlocks the solution toolbox for a wider class of algorithms.

Master Theorem

Definition

The Master Theorem is a "cookbook" method for solving recurrences of the form T(n) = aT(n/b) + f(n). It provides a direct template to determine asymptotic complexity by comparing the rate of growth of the recursive work (leaves) vs. the combination work (root).

It has three cases based on comparing n^{log_b(a)} with f(n):
1. Leaves grow faster -> Complexity is leaf-bound.
2. Rates are even -> Complexity is n * log n.
3. Root grows faster -> Complexity is root-bound.

Time & Space Complexity

Provides the answer immediately in Big-Theta (Θ) notation. It covers the vast majority of standard algorithms (Merge Sort, Binary Search, Stressen's).

What's it is for

Speed. During an exam or a whiteboard interview, you do not have time to draw a massive recursion tree or do an inductive proof. Master Theorem gives the answer in 10 seconds.

How it solve our problem

It reduces calculus to simple algebra. You just identify `a`, `b`, and `f(n)` and check inequalities. It acts as a pre-calculated lookup table for Differential Equations of algorithms.

Real world example

Corporate Management:
Case 1: The interns (leaves) do all the work. (O(n^x)).
Case 3: The CEO (root) does all the work. (O(f(n))).
The Theorem tells you who is the bottleneck in the organization hierarchy.

Why we choose only this rather than else

Substitution method requires a "guess" (Intuition). Iteration method is prone to algebra errors. Master Theorem is precise, mechanical, and less error-prone.

Unit 3: Divide and Conquer

Counting Inversions

Definition

An Inversion in an array is a pair of indices (i, j) such that `i < j` but `Arr[i]> Arr[j]`. It indicates how far an array is from being sorted. A sorted array has 0 inversions. A reverse-sorted array has max inversions.

The problem is to count the total number of such pairs. The naive approach generates n(n-1)/2 pairs.

Time & Space Complexity

Brute Force: O(n²).
Divide & Conquer: O(n log n) (Modified Merge Sort).
Space: O(n) for temporary array.

What's it is for

It is a measure of "disorder". Used in collaborative filtering to measure the difference between two people's rankings of a list of movies or products.

How it solve our problem

We hijack Merge Sort. During the Merge() step, if we pick an element from the Right subarray to be placed before the Left subarray, it means that Right element is "smaller" than all remaining elements in the Left subarray. We simply add `(mid - i)` to our count. We solve sorting and counting simultaneously.

Real world example

Spotify/Amazon: User A ranks songs [1,2,3]. User B ranks [3,2,1]. The number of inversions helps the algorithm decide if User B is similar to User A (low inversions) or opposite (high inversions).

Why we choose only this rather than else

For N=1,000,000 items, O(n²) is 1 trillion ops (too slow). O(n log n) is 20 million ops (instant). The D&C approach is the only viable one for big data.

Strassen's Matrix Multiplication

Definition

Strassen's Algorithm is a specific Divide and Conquer strategy for multiplying two n x n matrices. Unlike the standard method which takes 8 multiplications for 2x2 blocks, Strassen's uses a clever algebraic trick to do it in 7 multiplications.

Time & Space Complexity

Standard: O(n³).
Strassen: O(n^2.81).
For huge N, 2.81 is significantly smaller than 3.
Space: High O(n²) due to many temp matrices for recursion.

What's it is for

Used in high-performance computing (HPC) for large-scale scientific simulations, graphics rendering, and training Neural Networks (Deep Learning) where Matrix Multiply is the bottleneck.

How it solve our problem

It trades Additions for Multiplications. It explicitly calculates 7 intermediate terms (P1...P7) involving sums of sub-matrices. Then it constructs the result quadrants from these P terms. Since multipliers are slower than adders in hardware, reducing mults saves time.

Real world example

Graphics Cards (GPUs): Rendering a 4K game involves multiplying huge transformation matrices. Saving even 10% of operations results in higher FPS (Frames Per Second).

Why we choose only this rather than else

We actually don't choose it for small matrices (N < 100) because the overhead of recursion / additions is high. But for N> 2000, Strassen is mandatory to beat the O(n³) barrier.

Unit 4: Greedy Algorithms

Kruskal’s & Prim’s (MST)

Definition

Minimum Spanning Tree (MST): A subgraph that connects all vertices in a weighted graph with the minimum possible total edge weight, without cycles.
Kruskal's: Edge-centric. Sort all edges by weight, add smallest edge if it doesn't form a cycle.
Prim's: Vertex-centric. Grow a tree from a source node, always adding the cheapest edge connecting the Tree to the Outside.

Time & Space Complexity

Kruskal's: O(E log E) or O(E log V). Bound by sorting edges.
Prim's: O(E + V log V) using Fibonacci Heap.
Space: O(V + E).

What's it is for

Network Design. Laying cables, pipes, or roads to connect a set of cities/computers using the least amount of material.

How it solve our problem

Both use the "Greedy Choice Property". They prove that making the locally best choice (cheapest edge) at each step guarantees the globally optimal tree. No backtracking needed.

Real world example

Power Grid: You want to connect 50 houses to the power plant. Copper wire costs money per meter. MST algorithms tell you exactly which poles to connect to minimize total wire length.

Why we choose only this rather than else

We choose Kruskal for Sparse graphs (few edges) because it is simple to implement with Union-Find. We choose Prim for Dense graphs (many edges) because it visits every vertex efficiently.

Huffman Coding

Definition

Huffman Coding is a statistical data compression algorithm. It generates an optimal "Prefix Code" where frequently occurring characters get very short binary codes (e.g., '0') and rare characters get long codes (e.g., '10111'). It builds a binary tree bottom-up to determine these codes.

Time & Space Complexity

O(N log N) where N is the number of distinct characters, due to Min-Heap operations during tree construction.

What's it is for

Lossless Compression. Used in ZIP files, JPEG (final stage), and MP3. It reduces file size without losing a single bit of information.

How it solve our problem

It takes a greedy approach: "Combine the two rarest characters/subtrees into one." Repeating this ensures the rarest characters are at the bottom of the tree (longest path/code) and frequent ones are at the top.

Real world example

English Text: The letter 'e' appears 12% of the time. 'z' appears 0.07%. ASCII uses 8 bits for both. Huffman uses some 3 bits for 'e' and 10 bits for 'z'. Since 'e' is common, the total file size shrinks by ~40%.

Why we choose only this rather than else

It is the proven optimal symbol-by-symbol coding method. It is simple, fast, and requires no prior knowledge of the data string (adaptive variants exist). While Arithmetic Coding is slightly better, Huffman is faster/simpler.

Unit 5: Dynamic Programming

Binomial Coefficients & Making Change

Definition

Binomial Coeff: Computing "N choose K" (C(n,k)).
Making Change: Finding min coins to reach Value V.
Both are classic DP examples. Calculating C(n,k) via recursion involves massive overlap (`C(n,k) = C(n-1, k-1) + C(n-1, k)`). DP stores these.

Time & Space Complexity

Binomial: O(n*k) time and space.
Change: O(V*N) where V is value, N is number of coin types.
Compare to Recurisve C(n,k) which is O(2^n).

What's it is for

Binomial: Probability calculations, combinatorics.
Change: Electronic cash systems, resource optimization.

How it solve our problem

Pascal's Triangle: DP constructs the triangle row by row. To find row 5, we use values from row 4. No re-calculation.
Change: To make $10, we check (10 - coin1), (10 - coin2) and take the best of those computed sub-answers.

Real world example

Combinatorics: In Poker software, calculating the odds of a specific hand involves huge Binomial coefficients. Hardcoding them or using DP is essential for speed.

Why we choose only this rather than else

Recursion crashes for C(100, 50). The Greedy method fails for Change Making (if coins are {1, 3, 4}, Greedy for 6 is 4,1,1 (3 coins) but Optimal is 3,3 (2 coins)). DP is the only way to get the correct answer.

Floyd’s & chained matrix multiplication

Definition

Floyd-Warshall: An All-Pairs Shortest Path algorithm. It finds the shortest distance between every pair of nodes (u, v) in a graph.
Chained Matrix Mult: Finding optimal parenthesis placement for A*B*C*D... to minimize scalar multiplications.

Time & Space Complexity

Floyd: O(V³). Very structured.
Matrix Chain: O(N³).
Both are cubic algorithms that use a 2D/3D table.

What's it is for

Floyd: Dense graphs, Network routing tables.
Matrix Chain: Compiler optimization for scientific code.

How it solve our problem

Floyd's uses relaxation on intermediate nodes: `dist[i][j] = min(dist[i][j], dist[i][k] + dist[k][j])`. It iterates 'k' from 1 to V. Effectively, it checks limits "Allowing path through node 1", then "Nodes 1 and 2", etc.

Real world example

Airline Routing: Finding shortest flight paths between ALL cities on a map, not just from one hub.
Matrix Chain: Optimizing a deep learning pipeline efficiently.

Why we choose only this rather than else

Runing Dijkstra V times is complex to code and handles negative edges poorly. Floyd is 5 lines of code and handles negative weights (but not cycles). Use Floyd for implementation simplicity on small/dense graphs.

Unit 6: Graph Algorithms

DAG & Topological Sort

Definition

DAG: Directed Acyclic Graph. A graph with directions and NO loops.
Topological Sort: Ordering vertices such that for every edge u->v, u appears before v in the list. Impossible if a cycle exists.

Time & Space Complexity

O(V + E) using DFS or Kahn's Algorithm (In-degree method).
Space: O(V).

What's it is for

Dependency Resolution. Determining the sequence of events where some events must happen before others.

How it solve our problem

It linearizes a complex web of dependencies. The algorithm identifies nodes with "0 dependencies" (In-degree 0), processes them, effectively "removing" them, unlocking new nodes. This flows until the graph is empty.

Real world example

Software Installers (apt-get/npm): "To install Chrome, you need LibX. To install LibX, you need CoreLib." Topo Sort determines the install order: CoreLib -> LibX -> Chrome.

Why we choose only this rather than else

Standard sorting (lexicographical) doesn't respect graph edges. Topo Sort is the unique mathematical tool for scheduling dependent tasks.

Backtracking (Queens & Sum of Subsets)

Definition

Backtracking is a "systematic brute force". It builds a solution incrementally (step by step) and if it detects that the current partial solution cannot possibly be completed to a valid one, it abandons it ("backtracks") and tries a different path.
N-Queens: Place N queens on NxN board so no two attack each other.
Sum of Subsets: Find a subset of numbers that sum to K.

Time & Space Complexity

Time: Exponential O(N!) or O(2^N).
Space: O(N) (Recursion depth).
It is slow, but usually much faster than raw Brute Force because it "prunes" dead ends early.

What's it is for

Constraint Satisfaction Problems (CSP). Puzzles, Logic games, Configuration verification.

How it solve our problem

In N-Queens, we place a Queen in col 1. Then try col 2. If row 1 is attacked, we don't try placing there. We skip huge branches of the decision tree. It is a Depth First Search on the state space tree.

Real world example

Sudoku Solver: The computer tries a '5' in a cell. If it conflicts later, it backtracks and tries '6'.
Menu Planning: Finding a combination of foods that hit exact calorie targets (Subset Sum).

Why we choose only this rather than else

For N-Queens, there is no simple formula. We must search. Backtracking is the most efficient search for finding all solutions (not just one optimal one).

Unit 7: Computational Complexity

P, NP, NP-Hard, NP-Complete

Definition

P (Polynomial): Problems solvable in reasonable time (O(n), O(n²)). Easy.
NP (Nondeterministic Polynomial): Problems where a solution can be verified in reasonable time. (Hard to solve, easy to check).
NP-Hard: The hardest problems. If we solve one, we solve all NP problems.
NP-Complete: Problems that are in both NP and NP-Hard.

Time & Space Complexity

P problems runs in T(n) = O(n^k). NP-Complete problems currently accept only Exponential time algorithms O(2^n) or O(n!).

What's it is for

Classification of difficulty. It distinguishes between "We can optimize this" (P) and "This is inherently impossible to solve perfectly for large inputs" (NP-Hard).

How it solve our problem

This theory saves developers from losing their jobs. If your boss asks for an optimal Scheduling algorithm (NP-Complete), you can cite this theory to explain why you must use an Approximation algorithm instead of a perfect one.

Real world example

P: Sorting a deck of cards.
NP-Complete: Tetris (Optimally playing), Jigsaw Puzzles, Protein Folding.
NP-Hard: Halting Problem (Will this code overlap?).

Why we choose only this rather than else

Understanding this boundary is central to Computer Science. It defines the limits of computation. It guides us to use Heuristics (Genetic Algos, Simulated Annealing) when we hit an NP-Complete wall.

SAT & TSP

Definition

SAT (Satisfiability): Given a boolean formula (e.g., (A or B) and (not A or C)), can we assign True/False to variables to make the whole formula True?
TSP (Traveling Salesman): Find shortest route visiting all cities exactly once and returning to start.

Time & Space Complexity

Both are NP-Complete. Solving them for N=100 is feasible. Solving for N=100,000 would take longer than the age of the universe.

What's it is for

SAT is the basis of Formal Verification. TSP is the basis of Logistics and Manufacturing.

How it solve our problem

Cook's Theorem proved SAT was the "First" NP-Complete problem. All other problems like TSP are proved to be hard by converting ("reducing") them to SAT. If we could crack SAT, we would solve everything (P = NP).

Real world example

SAT: EDA Tools use SAT solvers to verify that a new Intel CPU design doesn't have logical bugs.
TSP: Amazon delivery trucks routing. They use "Heuristic TSP" to get a "good enough" route, because the "perfect" route is too hard to find.

Why we choose only this rather than else

We study these not to implement Brute Force, but to understand the structure of complexity and design Approximation Algorithms (getting within 1% of optimal in reasonable time).
